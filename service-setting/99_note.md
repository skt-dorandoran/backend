# 하면서 막힌 것들

## 목적

배포하면서 막힌 내용들을 정리하기 위함

## 1. 배포하기 위해서는 어떻게 해야 하는가?

폴더의 파일 내용대로 진행하면 됨

## 2. Dockerfile은 무엇인가?

Docker Image를 생성하기 위한 스크립트 파일, 나열된 명령문을 차례대로 수행하여 Docker의 Base Image를 토대로 새로운 컨테이너 Image를 생성

## 3. Docker와 Docker Compose의 차이점은 무엇인가?
- Docker: 단일 컨테이너를 관리 가능, CLI에서 실행됨
- Docker Compose: 복수의 컨테이너를 관리할 수 있는 클라이언트, yaml 파일+CLI를 통해 실행

## 5. 그래서 도커의 전체적인 작동 구조는 어떻고 각각의 구성요소는 무슨 역할을 하는가?

도커는 특정 환경을 관리하는 가상 컨테이너

내부에 Base image가 존재해야 코드를 실행할 수 있음

이 이미지는 Python 3.11.14-slim 등이 존재

컨테이너를 만들기 위해 Dockerfile이 필요

컨테이너를 만들기 위해서 빌드를 하면 도커 이미지가 만들어짐

실행 시
  - --name: 붙여야 컨테이너 명칭이 자동으로 붙지 않고 원하는 명칭으로 빌드 가능함
  - -d: daemon으로 실행, 백그라운드로 실행
  - -p: 좌측이 외부 포트, 우측이 컨테이너 서비스 포트
  - -v: 볼륨 설정, 필요한(계속 저장되어야 하는) 데이터에 대한 디렉토리를 연결하기 위함, (외부 경로:내부 경로) 형식으로 구성됨
  - 도커 이미지 명칭(빌드할 때 지정함)

도커 컴포즈는 야믈(.yml)로 다수의 컨테이너를 관리할 수 있게 함, 명령어 반복 안하고 편하기 하기 위함

## 6. GitHub Actions 스크립트에서는 무엇을 해야 하나?

이전에 직접 손으로 하던 일을 그대로 따라하도록 만들게 함

이 프로젝트의 경우
- 깃 리포 지우고 클론하기
- 이미지/컨테이너 올라가 있던거 내리고 지우기
- 이미지 빌드하고 컨테이너 올리기

## 7. deploy-api에 환경변수를 넣어야 하는가?

- 기본적인 환경변수: 컨테이너 명칭, 이미지 명칭, 네트워크 명칭 등
  - 이 변수들은 docker-compose.yml에서 자동으로 할당이 되고 임의로 넣으면 덮어씌워져 오히려 문제 발생
